# Backend Handoff Docs

**Purpose**: a self-contained handoff for the SLM Fine-Tuning Platform backend
— enough to understand the whole system, integrate a frontend against it, and
pick up development **without reading every line of code**.

**Audience**: the next developer on this backend, and the `smart-model-tune`
frontend/integration team consuming its API.

> **Where these files live / publishing note.** `docs/` is **default-private
> but selectively published**: `.gitignore` has `docs/*` followed by an explicit
> `!` allow-list, so a file here is only tracked once it is named there. Every
> document in the navigation table below **is** tracked and pushed; anything you
> add to `docs/` is **not**, until you add its `!` line. Directories need two
> entries (`!docs/adr/` *and* `!docs/adr/**`) — git will not descend into an
> excluded directory, so the `**` form alone silently keeps the whole folder out
> of the repo.
>
> The published spec is [`../openapi.json`](../openapi.json) at the repo root,
> regenerated by
> [`../scripts/export_openapi.py`](../scripts/export_openapi.py). There is no
> copy in this directory: `docs/openapi.json` used to exist as a "convenience
> mirror — re-copy after regenerating", and it drifted, because the export
> script writes the root file only. One file, no copying step.

**60-second orientation.** FastAPI + Celery + SQLAlchemy backend for an
automated Small Language Model fine-tuning platform. One pipeline, five stages:
**SDG** (synthetic data via OpenRouter) → **fine-tune** (Unsloth + QLoRA on GPU)
→ **export** (GGUF) → **serve** (Ollama) → **evaluate**. Exactly **3 task types**
— `classification`, `tool_calling`, `qa` — nothing else is supported. No auth.
See [`01-architecture.md`](./01-architecture.md) for the full picture.

## Consuming the API

- **Codegen a typed client** from `openapi.json` (`openapi-typescript`, `orval`,
  `openapi-generator`, …). All REST routes are under `/api/v1`.
- **Explore interactively** against a running API: Swagger UI at `/docs`, ReDoc
  at `/redoc`, raw spec at `/openapi.json`.
- **Live job progress** is a WebSocket, not in the spec — see
  [`03-realtime-websocket.md`](./03-realtime-websocket.md).
- **Regenerate** the spec after any contract change (don't hand-edit):
  `DATABASE_URL=postgresql+asyncpg://x:x@localhost/x python scripts/export_openapi.py`
  `tests/unit/test_openapi_spec_is_current.py` fails if you forget.

## Known discrepancies & gotchas surfaced during this handoff

Real inconsistencies found while writing these docs (all cited with `file:line`
inside the relevant doc). None are blockers — they're the traps a fresh
developer would otherwise hit. **Fixing them is future work, not done here.**

### Backend — stale docs/comments (code is correct, the words are wrong)
- **`README.md` says "7 services"; there are actually 9** in `docker-compose.yml`
  (it omits `minio-init` and `frontend`). — see `01-architecture.md`
- **`README.md` cross-links dead paths** (`require.md`,
  `docs/architecture/TECH_STACK.md`) that don't exist in this repo — hub docs
  were consolidated up a directory but the in-repo README wasn't updated.
  `docs/adr/` used to be in this same dead-link list but no longer is: it now
  exists in this repo (see the `adr/` row in the navigation table above),
  added alongside the realtime job-control work — `README.md`'s link to it
  is live again, this was just never updated to say so.
- **`training_service.py` docstring claims HPO is "currently 501"** — false; HPO
  is fully implemented and enqueues `train_hpo`. Stale comment. — see
  `02-api-reference.md`

### Backend — spec vs reality
- **`openapi.json` documents only success codes + a generic `422`.** The real
  `400/404/409/413/502` paths are raised via `HTTPException` in the service
  layer and are **absent from the spec** — a codegen'd client won't know they
  exist. `02-api-reference.md` documents the real error cases per endpoint.
- **`/trainings/{id}/loss-history` and `/metrics` return `200` with empty
  arrays/`{}`** when `mlflow_run_id` is still null — they do **not** 404 for
  "no data yet" (only for a non-existent `training_id`).
- **`export` accepts `format=lora` at the schema level** (legal `ArtifactFormat`)
  but the worker rejects it asynchronously — request-time it looks valid.

### Backend — vestigial / partial enum values
- **`SDGProgress.phase` includes `"format_detection"` but it's never emitted** —
  format detection runs synchronously during seed upload (HTTP), not inside the
  SDG job. Don't build UI expecting that phase. — see `03-realtime-websocket.md`
- ~~**`JobStatus.CANCELLED` only ever gets set by `TrainingJob`**~~ — **no longer
  true.** `Dataset`, `EvaluationRun` and `ModelArtifact.export_status` all reach
  `cancelled` now, via `POST /api/v1/datasets/{id}/cancel`,
  `/evaluations/{id}/cancel` and `/models/{id}/export/cancel`
  (`api/services/job_control.py` holds the shared semantics). — see `02-api-reference.md`
- **`EvaluationProgress.phase` includes `"scoring"` but it's never emitted** —
  metric computation is pure in-memory work, not a meaningful checkpoint, so no
  frame is published there. Same caveat as `format_detection` above.
- **`ai_engine/` imports Pydantic types from `api/schemas/*`** in a few places —
  no FastAPI/Celery imports (the real rule holds), but the layering isn't
  perfectly clean.

### `smart-model-tune` frontend — real integration breaks (detail in `04-…md`)
Re-verified against the frontend's current source on 2026-08-04 — several of
these were fixed in its 2026-07-30 pass. Full evidence per item in `04-…md`.

Fixed since first written (do not re-report):
- ~~SDG sends inline `seed_data`~~ → now sends `seed_dataset_id`.
- ~~`external_project_id` never sent~~ → now sent on create and used for recovery.
- ~~`TrainingMonitor` renders mock pipeline/log/loss-curve~~ → now real WS +
  `/trainings/{id}/loss-history`.
- ~~Playground silently falls back to canned responses~~ → shows the real error;
  the mock now only runs in dev builds.

Still real:
- **HPO report and Evaluation suite are 100% client-simulated** — nothing in
  `src/` calls `/evaluations` or submits `mode="hpo"`, though both exist.
- **`base_model="phi-3-mini"`** is blocked before launch now (maps to `null`),
  but is still the model of a template in `TemplateLibrary.tsx` → a dead end
  reached through a supported-looking path.
- **`ModelDetail.tsx` offers an ONNX export** the backend doesn't support
  (`ArtifactFormat` is `lora|gguf|safetensors`); its Download buttons have no
  handlers.
- **Deployment / API Keys / Analytics screens have no backend counterpart at
  all** — Supabase-only, with numbers nothing writes. See `04-…md` and ADR-006.

## Maintaining these docs

These are point-in-time (2026-07-29). When the contract changes: regenerate
`openapi.json`, then update `02-api-reference.md` (endpoints) and
`04-frontend-integration-smart-model-tune.md` (mapping) alongside the code
change — the same "don't let the mirror go stale" discipline that produced the
live `/api/v1/sdg-pipeline` endpoint instead of a hardcoded copy.
