Node 5 — Verify Generated Dataset

GET /api/v1/datasets/{id}   ·   GET /api/v1/datasets/{id}/preview   ·   GET /api/v1/datasets?project_id={id}

วัตถุประสงค์

ก่อนเริ่มเทรนต้อง verify ว่า dataset ที่ generate ออกมา (ทั้ง parent + holdout) มี:

  • จำนวน rows ตามที่ขอ
  • content / schema ถูกต้อง
  • parent ↔ child relationship ถูกต้อง (สำหรับ holdout flow)
  • generation_metadata รายงาน reject/dup count ที่ยอมรับได้

ขั้นตอนใน Swagger

5.1 ดู dataset detail (parent)

  1. GET /api/v1/datasets/{train_dataset_id} — ใส่ id จาก Node 4
  2. กด Execute
  3. ตรวจ num_samples, source, generation_metadata

5.2 ดู holdout child

  1. GET /api/v1/datasets/{holdout_dataset_id}
  2. ตรวจว่า parent_dataset_id = train_dataset_id

5.3 List datasets ทั้งหมดใน project

GET /api/v1/datasets?project_id=<uuid>&limit=20

ควรเห็น 3 rows:

  • seed (Node 3a)
  • parent (Node 4) — parent_dataset_id=null
  • holdout (Node 4) — parent_dataset_id=<parent>

Checklist ก่อนไป Node 6

เช็คค่าที่คาดหวัง
num_samples (parent)≈ num_samples ใน request
num_samples (holdout child)≈ holdout_size ใน request
parent_dataset_id (child)= parent id
judge_rejected_count< 30% ของ requested (ถ้าเกิน — task description กว้างไป)
Preview contentตรง task + อ่านได้
ถ้า preview แปลก ๆ: เช่น answer เป็น JSON สำหรับ qa, label out-of-set สำหรับ classification — กลับไปเช็ค task_description ที่ Node 4 ว่าชัดเจนพอไหม
