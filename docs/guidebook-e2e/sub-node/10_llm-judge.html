Node 10 — LLM as Judge

POST ASYNC 202 /api/v1/evaluations with use_llm_judge: true

วัตถุประสงค์

วัด qualitative quality ของ fine-tuned model ด้วย LLM-as-judge (rubric 1-5) — เสริม rule-based metrics จาก Node 9. ใช้เมื่อ:

  • BLEU/ROUGE สูงแต่ output แปลก ๆ → judge จะ catch
  • QA / open-ended task ที่มี multiple correct answers
  • เปรียบเทียบ models สอง trainings ที่ rule-based score ใกล้กัน

Prerequisite

  • เหมือน Node 9 ทุกอย่าง +
  • OPENROUTER_API_KEY ใน .env ของ api container (Node 9 ไม่ต้อง)

Request — minimal (ใช้ default judge model)

{
  "model_artifact_id": "<uuid>",
  "dataset_id": "<holdout_dataset_id>",
  "use_llm_judge": true
}

Request — เลือก judge_model เอง

{
  "model_artifact_id": "<uuid>",
  "dataset_id": "<holdout_dataset_id>",
  "use_llm_judge": true,
  "judge_model": "google/gemini-3.1-flash-lite-preview"
}
FieldDefaultNote
use_llm_judgefalseset true เพื่อ trigger judge
judge_modelLLM_JUDGE_MODEL ใน .env (ปัจจุบัน google/gemini-3.1-flash-lite-preview — ถูกที่สุดบน OpenRouter)OpenRouter model id — แนะนำให้ใช้ default ก่อน
Tip judge_model สำหรับ Thai content (QA Thai return policy, Classification Thai support): Gemini handle Thai ได้ดีกว่า Claude Haiku ของรุ่นเก่า. ใช้ default ของระบบ (gemini-3.1-flash-lite) ได้เลย — ราคาประมาณ $0.04 ต่อ 1k rows

Response 202 + GET result

GET /api/v1/evaluations/{evaluation_id}

{
  "id": "<uuid>",
  "status": "completed",
  "metrics_json": {
    "exact_match": 0.0,
    "rouge1": 0.286,
    "rouge2": 0.0,
    "rougeL": 0.286,
    "bleu": 0.020,
    "n": 5,
    "llm_judge_skipped_rows": 0
  },
  "llm_judge_score": 4.6,                          ← 1.0-5.0 mean
  "llm_judge_model": "anthropic/claude-haiku-4.5",
  "error_message": null,
  "started_at": "...",
  "ended_at": "..."
}
Judge ทำงานยังไง:
  • ส่งทุก row ของ holdout dataset → judge model พร้อม rubric 1-5
  • คิด mean score จาก rows ที่ judge parse ได้ (skip rows ที่ judge ตอบ JSON ไม่ถูก)
  • llm_judge_skipped_rows = จำนวน rows ที่ skip (ควรน้อยกว่า 10% ของ n)

Interpret score

Scoreหมายความ
4.5 – 5.0excellent — output ถูกต้อง + เขียนดี
3.5 – 4.5good — ถูกแต่อาจเป๋นิดหน่อย
2.5 – 3.5acceptable — partial answer หรือ phrasing แปลก
1.5 – 2.5poor — ผิด หรือ off-topic
1.0 – 1.5bad — fail ชัดเจน

Error cases

SymptomNote
llm_judge_score = null + skipped = njudge_model OpenRouter 404 — ลองเปลี่ยน judge_model
error_message = OPENROUTER_API_KEY emptyตั้ง env ใน api container + restart
Cost note: Judge เรียก OpenRouter 1 ครั้งต่อ row → ระวัง dataset ใหญ่. ใช้ holdout ที่ ~50-100 rows กำลังดี

Compare กับ baseline

POST /api/v1/evaluations/compare
{ "evaluation_ids": ["<rule-based-uuid>", "<judge-uuid>"] }

จะเห็น judge_scores ของ rule-based เป็น null, ของ judge run = float
