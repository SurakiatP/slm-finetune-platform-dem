E2E Test on VM — Playbook

Playbook สำหรับรัน 11-node E2E workflow ของ SLM Fine-Tuning Platform บน vast.ai (หรือ remote Linux VM ที่มี NVIDIA GPU) เพื่อ validate ว่า code path ทำงานครบจากจุดเริ่ม (create project) ถึงจุดสุดท้าย (LLM judge eval) ก่อนเปิด PR feature → dev

ใช้คู่กับ guide101.md (overview) + sub-node/*.html (per-node request/response detail) + vast-ai-deployment.md (VM setup detail).
Playbook นี้คือ recipe — sub-nodes คือ reference

3. Test Scope

Default smoke path: classification + with-seed (Node 3a → 4)

เลือก path นี้เพราะ
1. มี seed_data/classification/classification_canonical.jsonl พร้อม commit แล้ว → ไม่ต้องสร้าง seed
2. Metrics ง่ายอ่าน (accuracy) → debug ง่ายถ้าพัง
3. Node 4 exercise memory rule sdg_with_seed_no_task_config (ห้ามส่ง classification_config.labels เพราะ infer จาก seed)
4. Node 9 exercise GET /evaluations endpoint ที่เพิ่ม Session 24 + Node 10 exercise LLM judge surfacing (Session 23 Finding #2)

Training settings: 1 epoch, batch_size=2, gradient_accumulation=4, max_seq_length=512 (สำหรับ 8GB VRAM — ถ้า OOM ลดเป็น 1 / 256)

6. Phase C — 11-Node E2E ~15-20 min

ทำไม: validate code paths ที่ Sessions 21-25 แตะ — Node 4 (SDG holdout split), Node 6 (training), Node 7 (export+Ollama register), Node 9 (GET /evaluations เพิ่มใหม่), Node 10 (LLM judge — Finding #2 ปิด)

Test order: 1 → 2 → 3a → 4 → 5 → 6 + 11 (parallel) → 7 → 8 → 9 → 10

8. Success Criteria

  • ✅ Phase B: 176 passed, 3 skipped (ตรงกับ local baseline)
  • ✅ Phase C ทั้ง 11 nodes: ทุก request 2xx; all async jobs → completed; ไม่มี node ใด skip
  • ✅ Node 9: metrics_json.accuracy ≥ 0.2 (smoke threshold — proof of training, not production quality)
  • ✅ Node 10: llm_judge_score ≠ null และไม่ skipped — Finding #2 ปิดสนิท
  • ✅ ไม่มี OOMError / CUDA out of memory ระหว่าง Node 6

9. Risk Mitigation

RiskLikelihoodMitigation
Node 6 OOM @ 8GBMedium (1B + batch=2 ตึง)Fallback: batch=1, max_seq=256, gradient_accumulation=8
Node 4 OpenRouter ratelimitLowRetry built-in; ถ้า persist → switch judge_model เป็น cheaper
Node 7 Ollama register failsMedium (1B+adapter merge ใน 8GB ตึง)Continue — GGUF อยู่ใน MinIO inference path อื่นใช้ได้
Build timeout (>30 min)Low ที่ HF ~277 Mbpstmux survives; รอ — ถ้า <500 KB/s >5 min → destroy + new instance per runbook §3
Network drop ระหว่าง E2ELowPer-node response saved to /tmp ก่อน next node — resume ได้

11. Rollback by Phase

Failed PhaseAction
Phase A (build/up)SSH in → tmux capture-pane -t slm -p; ถ้า build < 500 KB/s > 5 min → destroy + new instance (per runbook §3)
Phase B (unit tests ≠ 176/3)Diff vs local; re-run pip install -e '.[dev]'; ตรวจ deps importable
Phase C mid-flowSave state ของ completed nodes (jsonl ใน /tmp); debug specific node; resume from failing node (most idempotent except project/dataset create)
Critical bug ใน Sessions 24/25 codeFlag in chat; ห้าม push fix จาก VM (no commit/push from VM — fix locally ใน session ถัดไป)
